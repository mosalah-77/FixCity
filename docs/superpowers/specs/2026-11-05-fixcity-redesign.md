# FixCity interface redesign

The user authorized an overnight redesign and will review the result afterward. Routine design choices can proceed. The supplied Figma deck is a reference, and the original app's working behavior must remain intact.

Use navy, muted gold and warm neutral surfaces, with teal for the main action. Use Cairo for Arabic and Latin text. Choose a simple street-and-location mark that reads at app-icon size. Present two alternatives separately; do not add a theme selector to the app. Keep government emblems out of the new identity.

Use Material navigation: Home, Reports, Alerts and Account on phones, a rail on wider screens. Move badges and settings into Account and retain their existing routes. Keep staff and district actions in the demo's role menu and a labelled work-tools menu, apart from resident tasks.

The home screen should lead with reporting and tracking, followed by the six existing categories and a compact report summary. The report form should explain its sequence and label required information. Keep the existing submission confirmation and backend validation. Staff report rows should open when tapped, with a clear next action in report detail. All changed controls must work with keyboard focus, RTL and larger text.

Humanizer applies to every public-facing sentence written or revised. Preserve facts, references, attribution and technical values. The public demo remains visibly labelled as synthetic, without real municipal delivery.

Validation covers both demo and normal modes, narrow Arabic layouts, navigation, draft retention, report submission, status updates, dark mode, browser and Android builds. CI must pass before publishing the redesigned browser demo. Physical Android testing remains a separate check.
